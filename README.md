# お礼状作成サポート

バージョン：v1.3.0

特別支援学校高等部の国語「お礼状」学習用の WEB アプリです。
生徒が①〜⑧の項目をワークシート形式で埋めていくと、日本語の縦書きのお礼状（清書用便箋）が自動的に完成し、そのまま印刷・画像保存できます。v1.1からは、その続きとして「封筒の書き方の見本」を作る機能も使えます。v1.1.1では、大きな機能追加は行わず、v1.1で追加した封筒機能を「より見やすく・教材として使いやすく・実運用しやすく」改善しました。v1.1.2では、お礼状本文・封筒の文字配置や表記を、縦書きとしてより自然に見えるよう細部を調整しました。v1.1.3では、実際に使ってみて見つかった次の3点を改善しました。
- 清書プレビュー（画面表示）の文字位置がずれて見える問題の修正
- 「会社あて」「個人あて」を選べるようにし、個人あての宛名（担当者名＋様）を正しく扱えるようにする改善
- 封筒表面の住所レイアウトの改善（できるだけ1列に収め、はみ出す場合だけ自然な位置で複数列にする）

v1.2では、新しく「郵便番号から住所を自動入力する機能」を追加しました。画面3で実習先の郵便番号（7桁）を入力すると、日本郵便が公式に公開している郵便番号データ（住所の郵便番号＋事業所の個別郵便番号）から住所を検索し、住所欄へ自動入力します。検索はすべて端末（ブラウザ）内で行い、郵便番号や住所を外部のサービスへ送信することはありません。詳しくは下記「郵便番号からの住所自動入力について」を参照してください。

v1.2.1では、実際に使ってみて見つかった次の3点を改善しました。
- 封筒表面の会社あて宛名を、「会社名」と「御中」が同じ1列の中に自然に続くレイアウトへ変更（個人あての「会社名」「担当者名＋様」の2列構成は変更していません）
- 画面2の氏名入力を「姓」「名」の2つの欄に分け、清書・封筒のどこに表示する場合も「姓＋全角スペース1文字＋名」の形に統一
- 画面右上に、現在のアプリバージョンを表示する小さなバッジを追加（表示専用で、タップ・クリックなどの操作は一切できません）

v1.2.2では、ワークシート①〜⑧のうち、②時候の挨拶と⑦結びの挨拶の入力を連動させました。
- ②・⑦のどちらを先に選んでも、月（および前半／後半）をもう片方へ自動的に反映
- 自動反映されたあとも、生徒がいつでも自由に選び直せる
- 生徒が一方を手動で変更したあとは、もう片方の選択済みの内容を勝手に上書きしない

v1.3.0では、これまで「現場実習」専用だったお礼状作成支援を、「職場見学」「その他」のお礼状にも使いやすい形へ拡張しました。
- 画面1の最初に「お礼状の種類」（現場実習／職場見学／その他）を選ぶボタンを追加（初期値は「現場実習」で、何も操作しなければ従来どおり使えます）
- ③お礼・⑥これからの基本文を、選んだお礼状の種類に応じて自動的に切り替え
- ③⑥は「文章を変更する」ボタンで必要なときだけ自由に編集でき、「基本文に戻す」で選んでいる種類の基本文へ戻せる
- 「その他」を選んだ場合は、用途を1つに決められないため、③⑥は最初から編集可能な状態になる
- ③⑥を生徒が一度編集すると、そのあとお礼状の種類を変更しても編集した文章は消えない（まだ編集していない場合だけ、種類の変更に合わせて基本文が切り替わる）
- ④具体的な出来事の説明文・書き出し（「実習では、」「見学では、」「今回は、」）も、お礼状の種類に応じて切り替え。すでに入力した本文はお礼状の種類を変更しても消えない
- ⑤心に残ったこと／学んだことは、どの種類でも使える内容のため変更していません
- ②時候の挨拶・⑦結びの挨拶の連動（v1.2.2）や、封筒（会社あて／個人あて・郵便番号自動入力など）には影響しません

## ファイル構成

| ファイル | 内容 |
| --- | --- |
| `index.html` | アプリの画面（画面1：ワークシート／画面2：清書／画面3：封筒） |
| `styles.css` | デザイン・配色・印刷用スタイル |
| `app.js` | 入力の処理、時候の挨拶・結びの挨拶のデータ、縦書きお礼状・封筒見本の自動生成 |
| `postal-data.json` | 郵便番号→住所の検索用データ（v1.2で追加。画面3で必要になったときに読み込む静的ファイル） |
| `scripts/build-postal-data.py` | 日本郵便の公式データから`postal-data.json`を作る開発・データ更新用スクリプト（アプリの実行時には使わない） |

React・Vue・データベース・サーバー・外部API・外部フォント・CDN は一切使用していません。HTML / CSS / JavaScript のみで動作する静的サイトです。

## 使い方

1. `index.html` をブラウザで開きます（GitHub Pages でそのまま公開できます）。
2. **画面1「お礼状を完成させよう」**
   - 最初に「お礼状の種類」（現場実習／職場見学／その他）を選びます（初期値は「現場実習」）。①頭語・⑧結語は常に固定です。
   - ③お礼・⑥これからは、選んだお礼状の種類に応じた基本文が最初から入っています（例：現場実習「先日は、現場実習で大変お世話になり、ありがとうございました。」）。必要な場合は「文章を変更する」ボタンで自由に書き換えられ、「基本文に戻す」でもとの基本文に戻せます。「その他」を選んだ場合は用途を1つに決められないため、③⑥は最初から自由に書ける状態になります。③⑥をすでに書き換えたあとにお礼状の種類を変更しても、書き換えた文章は消えません（まだ書き換えていない場合だけ、種類の変更に合わせて基本文が切り替わります）。
   - ②時候の挨拶・⑦結びの挨拶は、月を選ぶと「前半」「後半」の2つの文章カードが表示されるので、当てはまる方をタップして選びます。②・⑦は同じ時期に合わせることが多いため、v1.2.2からはどちらか一方で月や前半／後半を選ぶと、もう片方にも自動的に同じ月・前半／後半が反映されます（文章そのものは②・⑦それぞれの内容が選ばれます）。自動で反映された内容は、そのあと自由に選び直すことができ、一方を手動で変更しても、もう片方の選択済みの内容が勝手に書き換わることはありません。
   - ④具体的な出来事は、お礼状の種類に応じた書き出し（「実習では、」「見学では、」「今回は、」）に続けて生徒が入力します。お礼状の種類を変更しても、すでに入力した本文は消えず、書き出しだけが切り替わります。⑤心に残ったこと／学んだことは、文章のはじめから終わりまで生徒が自由に入力します（自動的に付け足される文章はありません）。
   - すべて入力できたら「作成完了」ボタンを押します。②③④⑤⑥⑦のいずれかが未入力の場合は、どこが不足しているかが日本語で表示され、清書画面には進みません。
3. **画面2「お礼状を清書しよう」**
   - まず「だれに送りますか？」で「会社あて」「個人あて」を選びます（初期値は「会社あて」）。
     - **会社あて**：実習先の会社名（必須）を入力します。清書・封筒では自動的に「（会社名）　御中」になります。
     - **個人あて**：実習先の会社名（必須）に加えて、「担当者名（敬称略）」（必須）を入力します。「様」は自動で付くため入力しないでください（入力欄の右に固定で「様」と表示されます）。清書・封筒では「（会社名）　（担当者名）　様」になり、「御中」は表示されません。「会社あて」に戻すと、入力済みの担当者名はそのセッション中保持されますが、清書・封筒には使われません。
   - 会社名が未入力のままでは「画像で保存」「印刷する」は実行できず、押すと「実習先の会社名を入力してください。」と表示されます。会社名を入力すると、この表示は自動的に消え、通常どおり保存・印刷できます。
   - 日付、学年を入力します。名前は「姓」「名」の2つの欄に分かれています（v1.2.1）。それぞれ入力すると、清書・封筒などの表示ではすべて「姓＋全角スペース1文字＋名」（例：「田川　渉」）にまとめて表示されます。画像のファイル名では、スペースなしの「田川渉」のように使われます。
   - 入力に合わせて、便箋プレビューに縦書きのお礼状がリアルタイムで反映されます（v1.1.3から、画面表示は「画像で保存」と同じCanvas描画に統一し、後半の行ほど文字位置がずれて見える問題を解消しました。詳しくは下記「清書プレビューについて」を参照）。
   - 日付は自動で「令和八年九月十二日」のような漢数字表記に変換されます（2019年5月1日以降を令和として計算）。
   - 便箋は縦罫線15列固定のA4便箋で、罫線は文章の量に関わらず紙面の上から下まで途切れずに表示されます。1列はおよそ25文字で右から左へ折り返しながら、本文→敬具→日付→学校名・学科学年（1つの列に連続して表示）→氏名→宛名の順に、1列ずつ続けて配置されます。
   - 敬具は最後の文章の次の列に配置され、列の下端から2マス空けた位置（下寄せ）に書かれます。日付・学校名情報・宛名は、それぞれの列の上から2マス空けた位置から書き始めます。氏名は敬具と同じく下寄せで、氏名の文字数が変わっても最後の文字が列の下端から2マス空いた位置に来るよう調整されます。
   - 敬具以降を「まとめて」次のページへ送ることはせず、1ページ目の残りの列を最後まで使い切ったうえで、本当に入りきらない分だけ自然に2ページ目へ続きます（1ページに収まる場合は不要な2枚目を作りません）。
   - 本文が15列に収まりきらない場合は、文字を縮小せずに同じレイアウトのまま自動で2枚目（必要であればそれ以上）の便箋を生成します。段落の途中でページが変わった場合は、2ページ目の冒頭で改めて一字下げをせず、文章をそのまま続けます。
   - 便箋プレビューは画面上では［2枚目］［1枚目］のように右から左の順（日本語の縦書き文書らしい並び）で表示され、開いた直後は1枚目が見える位置になっています。ただし印刷順は必ず1枚目→2枚目の順です。
   - 内容を確認したら「印刷する」ボタンでブラウザの印刷画面を開き、A4縦で印刷します（複数枚になる場合は、その枚数分のA4用紙に印刷されます）。
   - 保存の中心となるのは「画像で保存」ボタンです。Windows・Mac・iPhone・iPadのすべてで同じボタン（同じ見た目）が表示され、便箋のページだけをPNG画像として書き出します。押すと簡単な案内が表示され、「画像を保存する」を押すと保存・共有が始まります。
     - **Windows・Mac などのPC**：画像のダウンロードが自動的に始まります（複数ページの場合は1ページずつ順にダウンロードされます）。続けて画像の一覧プレビューも表示されるので、うまくダウンロードできなかった場合はそちらの「この画像を保存」からページごとに保存できます。
     - **iPhone・iPad**：端末の共有画面（共有シート）が開き、「画像を保存」または「”ファイル”に保存」を選んで保存できます。共有画面が使えない・失敗した端末では、代わりに画像のプレビューが表示されるので、画像を指で長く押すか「この画像を保存」から保存してください。
     - ページが2枚以上ある場合は、どちらの端末でも1ページずつ別々の画像として書き出されます（1枚の長い画像には連結しません）。画像は便箋の部分だけが対象で、タイトル・入力欄・ボタンなどの操作用UIは含まれません。
   - 「もどって直す」を押すと画面1に戻り、入力内容はそのセッション中は保持されます。
   - 「封筒へ進む」を押すと画面3（封筒）に進みます。**会社名・姓・名のいずれかが未入力の場合、また「個人あて」なのに担当者名が未入力の場合は進めません**。未入力の項目に応じて「封筒を作るために、実習先の会社名を入力してください。」「封筒を作るために、担当者名を入力してください。」「封筒を作るために、姓を入力してください。」「封筒を作るために、名を入力してください。」（複数未入力の場合はまとめて伝える文章）が日本語で表示されます。
4. **画面3「封筒を書こう」**（v1.1で追加、v1.1.1／v1.1.2／v1.1.3で改善）
   - 実習先の会社名・宛先の種類（会社あて／個人あて）・担当者名・生徒氏名は画面2の入力をそのまま引き継ぐため、画面3での再入力は不要です。画面上部に「宛先：」として、会社あてなら「（会社名）　御中」、個人あてなら「（会社名）」と「（担当者名）　様」の確認表示があり、その下に生徒本人の氏名も表示されます。宛先を直したいときは「清書にもどる」で画面2に戻って修正してください（v1.1.3から、担当者名の入力欄は画面2に一本化し、画面3では二重に入力しない仕様にしました）。
   - 実習先の郵便番号（必須）・実習先の住所（必須）を入力します。郵便番号・住所が未入力のまま「画像で保存」「印刷する」を押すと、実行されずに日本語で分かりやすいメッセージが表示されます。
   - 郵便番号を7桁入力すると、住所を自動検索して住所欄へ入力します（v1.2）。番地・建物名など残りの部分は続けて手入力してください。詳しくは下記「郵便番号からの住所自動入力について」を参照してください。
   - 画面上のプレビューは「表面」「裏面」の切替タブになっており、入力に合わせてリアルタイムで更新されます。1つの面を大きく表示するため、スマートフォンでも文字が読みやすくなっています（印刷・画像保存のレイアウト自体は変わりません。下記「封筒について」を参照）。
   - 封筒の裏面には、学校の郵便番号（「〒338-0824」のような通常の文字列表記）・住所・学校名（正式名称）・生徒氏名を、封筒の左半分にまとまるように配置しています（右半分は余白）。学科・学年は表示しません。学校情報は固定データを使うため、毎回入力する必要はありません。
   - 実習先の住所は、よほど長くない限り1列に収まるように表示し、本当に収まらない場合だけ、数字＋ハイフン（例：「1-2-3」）や「丁目」「番地」などが不自然な位置で分かれないよう配慮しながら2列目以降へ続けます（詳しくは下記「封筒について」を参照）。
   - 入力欄をタップ（フォーカス）すると、その入力欄が画面上で見える位置まで自動でスクロールするため、スマートフォンでキーボードが表示されているときも、今どの欄を編集しているか分かりやすくなっています。
   - この見本は**長形3号（120mm×235mm）を基準にした「手書き用の見本」**です。実際の封筒に直接印刷する機能ではありません。「印刷する」を押すと、表面・裏面を並べたA4横向き1枚の見本が印刷されます。「画像で保存」を押すと、表面＋裏面をまとめた1枚のPNG画像として保存されます（画面2の「画像で保存」と同じ考え方で、iPhone・iPadは共有画面、Windows・Macなどは自動ダウンロード＋プレビューになります）。iPhone・iPadの共有画面では、タイトル「封筒見本」・説明文「封筒の見本画像です。」が表示され、便箋を保存したときとは区別されます。
   - 「清書にもどる」を押すと画面2に戻ります。画面2で宛先の種類・会社名・担当者名・氏名を修正して再び画面3に進むと、変更後の内容が封筒にも反映されます。郵便番号・住所は、ページを開いている間は入力内容が保持されます。
5. 印刷した用紙、または保存した画像を見本にして、生徒が実際の便箋・封筒に手書きで清書します。

## 個人情報・データの扱いについて

- 入力した氏名・会社名・宛先の種類（会社あて／個人あて）・担当者名・文章・封筒の郵便番号／住所などは、**ブラウザのメモリ上でのみ**扱われます。
- サーバーへの送信、外部API・AI APIとの通信、localStorage・Cookieへの保存、アクセス解析への送信は一切行いません。
- v1.2の郵便番号からの住所自動入力も、外部の郵便番号検索APIは使用していません。アプリと同じ場所（GitHub Pages）に置かれた`postal-data.json`（郵便番号の検索データ）を読み込み、検索はすべてブラウザの中だけで行います。入力した郵便番号や、その検索結果が外部へ送信されることはありません。
- ページを再読み込みしたり閉じたりすると、入力内容はすべて消えます。

## 清書プレビューについて（v1.1.3で修正）

- 画面2の清書プレビューは、以前はHTML/CSSの縦書き（`writing-mode: vertical-rl`）でそのまま表示していましたが、CSSのフォント縦方向の実測間隔が想定どおりに揃わないことがあり、本文の後半（下の方の列）ほど文字位置が少しずつずれて見える問題がありました。「画像で保存」で書き出すPNG画像はCanvasへ直接描画しているため、この問題は起きていませんでした。
- v1.1.3から、画面プレビューも「画像で保存」と同じCanvas描画（`renderPageCanvas`）を使うように統一しました。これにより、画面で見た文字位置と保存されるPNG画像の文字位置が常に一致するようになり、後半ほどずれる問題は解消されています。
- 横スクロールで複数ページを確認できる操作性や、開いた直後に1枚目が見える位置になっている挙動、［2枚目］［1枚目］の並び順は変更していません。
- ブラウザの「印刷する」機能で使われるA4縦の便箋は、これまでどおりHTML/CSSのDOM（`#paper-wrap`）で生成しており、画面表示専用のCanvasプレビューとは別に、印刷時だけ表示される仕組みです。印刷のレイアウト・改ページの仕組み自体は変更していません。

## 印刷について

- 「印刷する」ボタンは、`@media print` により、印刷時はタイトル・説明文・入力欄・ボタンなどの操作用UIをすべて非表示にし、清書用便箋だけを印刷します。
- 用紙サイズはA4縦、余白は一般的な家庭用・学校用プリンターで切れない範囲に設定しています。
- 便箋が2枚以上になる場合は、1枚ごとに改ページして印刷されます（`break-after: page`）。画面上のプレビューは縦書き文書らしく［2枚目］［1枚目］の順に見えますが、印刷順は必ず1枚目→2枚目のままです。
- 画面上でスマートフォン・タブレット向けに使っている横スクロール・行の逆順表示（`flex-direction: row-reverse`）・拡大縮小などのレイアウトは、あくまで画面表示専用で、印刷時にはすべて解除されます。
- 端末がダークモード（画面を黒基調で表示する設定）になっていても、印刷の用紙は必ず白背景・黒文字で出力されます（`color-scheme: light` を明示指定）。
- 極端に長い文章を入力すると便箋の上限枚数を超える場合があります。その際は画面上に注意メッセージを表示するので、④や⑤の文章を短くしてください。
- 以前はPC向けに「PDFで保存」（`window.print()`を使った印刷画面経由の保存）ボタンもありましたが、MacBook・iPhone・iPadではSafariの印刷・PDF化でページ数が増えたり黒背景になったりする問題があり、PC側でも保存結果が安定しなかったため、保存の主手段は下記の「画像で保存」に一本化しました。「印刷する」ボタン自体（と、その印刷レイアウト）はそのまま残っています。

## 画像で保存について（全端末共通）

- Windows・Mac・iPhone・iPadのすべてで、保存機能は「便箋のページだけを画像として保存する」方式に統一しています。PDF保存機能（PDF専用の案内・端末別のPDF案内など）は廃止しました。
- 画像化にあたって外部ライブラリ（`html2canvas` など）やCDNは使用していません。清書のレイアウトで使っている列数・1列の文字数・余白・フォントサイズなどと同じ計算式を使い、`<canvas>`に縦罫線と文字を直接描画してPNG画像を作っています。
  - 当初はDOM（完成した便箋の見た目そのもの）をSVGの`foreignObject`で複製してcanvasに描画する方式を試しましたが、`foreignObject`を含むSVG画像をcanvasに描画すると、内容に関係なくブラウザの仕様上「読み取り禁止（tainted canvas）」扱いになり、PNGとして取り出せないことが分かったため、この直接描画方式に変更しました。画面表示用の横スクロールや縮小表示の影響を受けず、常に実寸のA4サイズを基準にレンダリングするため、画面がどんな表示状態でも同じ結果になります。
  - `html2canvas` は縦書き（`writing-mode: vertical-rl`）に対応していないため、今回の用途には使用していません。
- 画像は常に白背景・黒文字で書き出されます（端末がダークモードでも影響を受けません。canvasへ描画する色を固定しているため、画面側の見た目に関わらず常に同じ結果になります）。印刷見本として使えるよう、画面の等倍よりも高い解像度（3倍）で書き出しています。
- 縦書きの句読点（、。）は、通常の文字と同じ大きさ・中央位置で描画すると不自然に見えるため、一回り小さく、セルの右上寄りに描画しています（v1.1.2）。
- 保存・共有の方法は端末によって異なります。
  - **iPhone・iPad**：Web Share APIで端末の共有画面を開きます。使えない・失敗した場合は画像のプレビュー画面を表示し、長押し、または画像ごとの「この画像を保存」から保存できます。
  - **Windows・Mac などのPC**：画像を自動的にダウンロードします。そのうえで画像の一覧プレビューも表示するため、自動ダウンロードがうまくいかない場合でも、ページごとに手動で保存できます。
- ページが2枚以上ある場合は、ページごとに別々のPNG画像になります（1枚の長い画像に連結することはありません）。ファイル名には日付・氏名・ページ番号を含めます（例：`お礼状_20260915_田川渉_1ページ目.png`）。
- 画像の生成や保存に失敗した場合は、分かりやすいエラーメッセージを表示します。

## 封筒について（v1.1で追加、v1.1.1／v1.1.2／v1.1.3／v1.2.1で改善）

- 「封筒作成サポート」は、**長形3号（120mm×235mm）を基準にした、生徒が手書きで清書するための見本**を作る機能です。実際の封筒へ直接印刷したり、宛先を自動で印字したりする機能ではありません。
- 表面には切手を貼る場所（郵便料金は改定されるため表示しません）・実習先の郵便番号（3桁＋4桁の7マス）・実習先の住所（縦書き）・会社名＋宛名（御中、または担当者名＋様）を配置しています。裏面には学校の郵便番号（通常の文字列表記）・住所・正式な学校名・生徒氏名を配置し、封筒の継ぎ目・フラップも簡単な線で表現しています。
- 宛先が「会社あて」か「個人あて」かは画面2で選ぶため（上記「使い方」参照）、封筒表面の宛名も自動的に切り替わります。**会社あて**：「会社名」と「御中」を、全角スペース2文字分の空白を挟んで同じ1列の中に続けて表示します（v1.2.1。以前は会社名と御中を別々の列に分けていましたが、実際の手書き見本として自然に見えるよう、1本の縦列にまとめました）。**個人あて**：会社名の列とは別に、その左隣の列へ「担当者名＋様」を1つの列としてまとめて表示し、会社名より少し下げた位置から書き始めます（担当者名と「様」を別々の列に分けることはしません。この個人あてのレイアウトはv1.2から変更していません）。どちらの場合も「御中」と「様」が同時に表示されることはありません。
- 実習先住所・学校住所（縦書き）は、数字を1文字ずつ漢数字に変換して表示します（例：「519-7」の場合、5・1・9・7がそれぞれ「五」「一」「九」「七」になります）。あわせて、住所中のハイフンは縦書きでは横線のままだと不自然なため、縦線として表示します（v1.1.2）。入力欄そのものの値は変更せず、封筒の描画時だけ変換しています。実習先・学校の郵便番号は、この変換の対象外で、これまでどおり数字のまま表示します。
- **画面プレビューと印刷・画像保存は、あえて別のレイアウトにしています。**
  - **印刷・画像保存**：これまでどおり、表面・裏面をA4横向き1枚に並べたレイアウトのまま変更していません。「印刷する」を押すとその内容でA4横向き1枚に印刷され、「画像で保存」を押すと表面＋裏面をまとめた1枚のPNG画像として保存されます（便箋のようにページごとに複数画像になることはありません）。長形3号を実寸で表示するのではなく、A4用紙に収まる大きさに縮小しています。
  - **画面プレビュー**：スマートフォンではA4横1枚のレイアウトのままだと文字が小さくなりすぎるため、v1.1.1から「表面」「裏面」を切り替えるタブ形式にし、1面ずつ大きく表示するようにしました。印刷・画像保存専用の`<canvas>`とは別に、プレビュー専用の`<canvas>`を用意し、入力するたびにプレビュー側だけを再描画しています（印刷・画像保存用のcanvasは、実際に「印刷する」「画像で保存」を押したときにそのつど最新の内容で描画するため、出力結果は変わりません）。
- 印刷は、清書（便箋・A4縦）とは別に、封筒画面だけA4横向きで印刷されるようにしています（`<style id="dynamic-page-style">`を使い、印刷ボタンを押した直前にA4縦／A4横のどちらを使うかをJavaScriptで切り替えています）。便箋の印刷レイアウトには影響しません。
- 画像保存の仕組みは便箋と同じ考え方（`<canvas>`への直接描画、外部ライブラリ・CDN不使用、常に白背景・黒文字）です。iPhone・iPadで画像を保存するときの共有画面には、便箋とは区別できるよう封筒専用のタイトル・説明文（「封筒見本」／「封筒の見本画像です。」）を表示します。
- 学校名・学校住所・学校郵便番号は封筒裏面専用の固定データです。清書（便箋）で使っている学校名「さいたま桜高等学園」とは別に、封筒裏面では正式名称「埼玉県立特別支援学校さいたま桜高等学園」を使用しています。裏面ではこれらの差出人情報（郵便番号・住所・学校名・氏名）を封筒の左半分にまとめて配置し、右半分は余白として残しています。
- 実習先の住所・学校住所は、単純に文字数で区切るのではなく、漢数字＋縦線（ハイフンの変換後の表記）の並びや「丁目」「番地」をできるだけ崩さず、1文字だけの列ができないよう調整する簡易的なロジックで縦書きの列に分割しています（完全な住所解析ではありません）。
- 封筒**表面**の実習先住所は、v1.1.3から「よほど長い住所でない限り1列に収める」ことを基本にしました。書き始めの位置・1文字あたりの縦方向のピッチ・封筒の高さ・下側の余白（約5マス分）から、1列に入る文字数をそのつど計算し、収まる住所は固定の文字数で区切らず1列のまま表示します。本当に1列で収まらない長い住所だけ、上記の分割ロジックで2列目以降に自然に続けます。2列目以降は上詰めではなく、残った文字数から書き始め位置を逆算し、最後の文字が下から約5マス空けた位置に来る「下揃え」で表示します（短い続きの住所が上の方に浮いて見えないようにするためです）。この改善は封筒**表面**（実習先住所）が対象で、封筒**裏面**（学校住所）の位置・レイアウトはこれまでどおり変更していません。
- 表面は、住所の列と会社名の列の間隔を広めに取り、会社名の列がやや中央寄りに見えるよう調整しています。

## 郵便番号からの住所自動入力について（v1.2で追加）

- 画面3「実習先の郵便番号」に数字7桁がそろうと、自動的に住所を検索し、「実習先の住所」欄へ反映します。検索ボタンを押す必要はありません。「3300856」のように数字だけで入力しても、「330-0856」のようにハイフン入りで入力しても、同じ郵便番号として検索します（数字だけで7桁入力し、そのままカーソルが末尾にある場合は「330-0856」の形へ自動整形することもあります）。
- 検索には、日本郵便が公式に公開している2種類の郵便番号データを、あらかじめアプリ用に変換した`postal-data.json`を使います。
  - **住所の郵便番号**（いわゆる通常の郵便番号。1つの郵便番号に町域まで対応）
  - **事業所の個別郵便番号**（大口事業所が個別に持つ郵便番号）。実習先が独自の郵便番号を持つ企業・団体である場合も、できるだけ住所を自動入力できるようにするためのものです。
- `postal-data.json`は、画面3へ最初に進んだタイミングで読み込みます（外部APIへの問い合わせではなく、アプリと同じ場所にある静的ファイルの取得です）。読み込みに少し時間がかかる場合は、郵便番号欄の下に「住所データを読み込んでいます…」と表示します。
- **住所候補が1件だけ見つかった場合**：住所欄が空、またはアプリが直前に自動入力した住所のままであれば、そのまま自動入力し、「郵便番号から住所を自動入力しました。番地・建物名などを続けて入力してください。」と案内します。事業所の個別郵便番号だった場合は、その事業所名も案内に添えます（画面2で入力済みの会社名を書き換えることはありません）。
- **生徒がすでに住所を手入力・修正している場合**：新しい検索結果があっても自動では上書きしません。「郵便番号から住所が見つかりました。」と表示し、「住所に反映」ボタンを押したときだけ反映します。
- **住所候補が複数見つかった場合**：どれか1つを勝手に選ばず、「住所を選んでください。」として候補を一覧表示します（事業所の個別郵便番号の場合は事業所名も添えて表示します）。生徒が候補を選ぶと、その住所を住所欄へ反映します。
- **住所が見つからなかった場合**：「住所が見つかりませんでした。郵便番号を確認してください。住所はそのまま手入力することもできます。」と案内します。この場合も含め、住所欄はいつでも自由に手入力・編集できます。郵便番号の自動検索に失敗しても、封筒作成自体ができなくなることはありません。
- `postal-data.json`の読み込み自体に失敗した場合（回線状況などにより）も、アプリ全体は止まりません。「住所の自動入力を利用できません。住所を手入力してください。」と表示し、これまでどおり郵便番号・住所を手入力すれば封筒を作成できます。
- 自動入力・選択された住所も、封筒プレビューでは既存の仕様（数字を漢数字に変換、縦書きのハイフンを縦線「｜」で表示、郵便番号は算用数字のまま、住所はできるだけ1列・長い場合のみ複数列で下揃え）がそのまま適用されます。
- 日本郵便の住所データには、町域が未確定の代表行として「以下に掲載がない場合」という表記が含まれることがあります。この文字列はそのまま住所欄に入れず、都道府県＋市区町村までを自動入力します。
- この機能はあくまで検索・自動入力の補助です。実際の郵便番号・住所は、必ず生徒自身が実習先の書類などで確認してください。

## 郵便番号データの更新方法

`postal-data.json`は、日本郵便の公式データを`scripts/build-postal-data.py`で変換して作成しています。このスクリプトは開発・データ更新用で、アプリの実行時には使用しません。データを最新化したいときは、次の手順で行ってください。

1. **日本郵便公式サイトから元データをダウンロードする**
   - ダウンロードページ：https://www.post.japanpost.jp/zipcode/download.html
   - 住所の郵便番号（UTF-8版・`utf_ken_all.csv`を使用）：同ページの「読み仮名データの促音・拗音を小書きで表記するもの」の項目にある「utf_ken_all.zip」のリンクから取得してください。
   - 事業所の個別郵便番号（`JIGYOSYO.CSV`、Shift-JIS）：同ページの「大口事業所の個別郵便番号」の項目にある「jigyosyo.zip」のリンクから取得してください。
   - どちらのデータも、日本郵便株式会社は著作権を主張しておらず、自由に配布・利用できます（各ダウンロードページの利用条件を参照）。直接のダウンロードURLはサイト側の都合で変わることがあるため、本READMEには記載せず、上記ダウンロードページから毎回たどることを推奨します。
2. **ダウンロードしたzipを展開する**
   - 展開した`utf_ken_all.csv`と`JIGYOSYO.CSV`を、任意の場所（例：`scripts/source-data/`、Git管理対象外）に置きます。
3. **変換スクリプトを実行する**

   ```bash
   python3 scripts/build-postal-data.py \
     --ken-all scripts/source-data/utf_ken_all.csv \
     --jigyosyo scripts/source-data/JIGYOSYO.CSV \
     --out postal-data.json
   ```

   外部ライブラリを追加インストールする必要はなく、Python 3標準ライブラリだけで動作します。
4. **`postal-data.json`を置き換える**
   - リポジトリ直下の`postal-data.json`を、生成した新しいファイルで置き換えてコミットしてください。
   - スクリプト自体（`scripts/build-postal-data.py`）や、ダウンロードした元CSVはアプリの動作に必須ではありません。元CSVはリポジトリに含めず、手元だけで保管することを推奨します。

**制限事項**：住所データの中には、1つの町域名が非常に長く複数行に分けて記録されている場合がありますが、このスクリプトはそれらを結合する処理までは行っていません（既存の住所分割ロジックと同様、完璧な住所解析は目指していません）。町域名の表記が不自然に見える場合は、生徒が住所欄で自由に修正してください。

## 画面右上のバージョン表示について（v1.2.1で追加）

- 画面右上に、現在のアプリのバージョン（例：「v1.2.1」）を小さな角丸バッジで表示します。①ワークシート・②清書・③封筒のどの画面でも、共通のヘッダーから同じ表示を確認できます。
- この表示は**完全に表示専用**です。タップ・クリック・リンク・長押しメニューなど、一切の操作を持ちません（`pointer-events: none` を指定しており、押しても何も起こりません）。
- バージョン番号は`app.js`内の`APP_VERSION`という変数1か所だけで管理しています。HTMLに`v1.2.1`のような文字列を直接書き込むことはせず、画面のバッジは常に`APP_VERSION`から自動的に生成されます。今後バージョンを更新する際は、`APP_VERSION`の値を書き換えるだけで、画面の表示も自動的に変わります（`README.md`冒頭のバージョン表記も、リリース時にあわせて更新してください）。
- バージョンバッジは、ヘッダーと同じく印刷（`@media print`）では非表示になり、お礼状・封筒のPNG画像にも含まれません（画像はCanvasへの直接描画のみで作られており、画面のヘッダー部分を参照する仕組みではないため）。

- 画面幅が狭い端末でもワークシート・便箋の入力操作ができるレスポンシブデザイン
